# 活用 · Conjugación

Japanese verb and adjective conjugation drills up to JLPT N3, plus grammar fichas, with a
Spanish interface and Spanish meanings. Static site, no build step, deployable to GitHub Pages as is.
Three sections share one tab bar: **動詞 Verbos** (`index.html`), **形容詞 Adjetivos**
(`adjetivos.html`, see below) and **文法 Gramática** (`gramatica/`).

Each question takes a random verb and a random form:

| Dimension | Options |
|---|---|
| Voice / base | 基本 · 可能 · 受身 · 使役 · 使役受身 · たい |
| Inflection | 現在 · 過去 · て · ば · たら · たり · 意向 · 命令 · ながら · そう |
| Polarity / register | 肯定/否定 · 普通/丁寧 (where the form has them) |

| Auxiliaries | 〜ている · 〜てしまう · 〜てある · 〜ておく · 〜てみる · 〜ていく · 〜てくる · 〜てあげる/くれる/もらう (+ さしあげる/くださる/いただく) · 〜すぎる · 〜たがる · 〜ことができる · 〜ようになる |
| Keigo | お〜になる (尊敬語) · お〜する (謙譲語), with the suppletive verbs (いらっしゃる, 参る, 伺う…) |
| Set expressions | 〜ても · 〜てもいい · 〜てはいけない · 〜なければならない · 〜てください · 〜ていただけませんか · お〜ください · 〜てごらん · 〜たことがある · 〜(よ)うと思う · 〜つもりだ · 〜ほうがいい · 〜たばかりだ · 〜そうだ (hearsay) · 〜ふりをする · 〜っぱなし |

Only real combinations are asked (332 forms; no potential volitional, no 〜たい imperative, …).
The auxiliaries, keigo and expressions are the verb patterns of the Notion *Verbos* and
*Variado* lists; each declares in `js/conjugate.js` which inflections it takes and which verbs
it fits (〜てある transitive only; 〜てみる, 〜てあげる and keigo only volitional verbs, listed in
`VOL_INTR` for intransitives).
Type in romaji (converted live by WanaKana) or with a Japanese IME; kana and kanji
answers are both accepted. Missed questions come back four turns later.
After each answer the verb's Notion example sentence is shown rewritten in the
asked form, with a Spanish translation, next to the original.
Settings and per-form accuracy are kept in `localStorage`.

## Layout

```
index.html               verb drill page
adjetivos.html           adjective drill page
css/tokens.css           colour and font tokens for every page (light + dark)
css/ficha.css            shared styles of the grammar fichas
js/conjugate.js          verb conjugation engine (pure, also require()-able from Node)
js/adjconj.js            adjective engine (reuses conjugate.js for 〜すぎる / 〜くなる)
js/app.js                quiz UI shared by both drills
js/drill-verbos.js       per-page configuration read by app.js (word list, engine,
js/drill-adjetivos.js      settings groups, localStorage prefix conj: / adj:)
ayuda.html               help pages (reference tables generated by the engines)
ayuda-adjetivos.html
gramatica/               grammar fichas + generated index (see below)
js/vendor/wanakana.*     romaji → kana IME (MIT)
data/verbs.js            GENERATED verb list — do not edit
data/adjectives.js       GENERATED adjective list — do not edit
scripts/build_verbs.py   builds data/verbs.js from the Notion snapshot
scripts/build_adjectives.py  builds data/adjectives.js from the same snapshot
translations/es/*.txt    hand-written Spanish for each rewritten example
scripts/build_translations.js  validates them -> data/examples_es.js (GENERATED)
tests/test_conjugate.js  verb engine tests
tests/test_adjconj.js    adjective engine tests
```

## Adjective drill (`adjetivos.html`)

Same quiz, same UI (`js/app.js`), separate settings and stats. The list is the Notion
**Adjetivos** database (い and な; prenominals such as 主な or 次の are left out, and
`SKIP` in `build_adjectives.py` drops 大きな and the suffix 難い). Forms asked (79):

| Dimension | Options |
|---|---|
| Base | 基本 · 〜すぎる · 〜くなる/〜になる (the last two become verbs, inflected by `conjugate.js`) |
| Inflection | 現在 · 過去 · て · ば/なら · たら · たり · adverb (く/に) · そう (appearance) |
| Expressions | 〜ても · から · ので · のに · そうだ (hearsay) · ようだ · みたいだ · らしい · かもしれない · だろう/でしょう |

The expressions are there for the な / だ / nothing a な-adjective takes in front of each
(静かなので, 静かだから, 静かかもしれない). いい and its compounds conjugate on よ
(かっこよかった, 頭がよくて). Per-word exceptions (no negative for 元気がない, no そう for
綺麗 or 可愛い, no adverb for 好き…) are the `NO_*` sets at the top of `js/adjconj.js`.
There is no Spanish for the rewritten example yet: the original Notion sentence and its
translation are shown under it.

## Updating the word lists

The verbs and adjectives come from the Notion **Verbos** and **Adjetivos** databases via the
snapshot kept by `../anki/notion_sync.py` (sibling folder in the `Japanese` repo). Its `pull`
runs both build scripts itself, so after a pull only tests, version bump, commit and push remain.

```bash
python3 ../anki/notion_sync.py pull      # refresh the Notion snapshot (needs NOTION_TOKEN); rebuilds both lists
python3 scripts/build_verbs.py           # -> data/verbs.js       (also run by pull)
python3 scripts/build_adjectives.py      # -> data/adjectives.js  (also run by pull)
node tests/test_conjugate.js             # every verb × every form must conjugate
node tests/test_adjconj.js               # every adjective × every form
node scripts/build_translations.js       # -> data/examples_es.js; reports stale entries
node scripts/build_translations.js --todo  # verbs whose example still needs Spanish
```

Each translation entry holds present / negative / past / negative past per voice
(plus volitional and imperatives for plain and causative); the connective forms
(ば, たら, て, たり, ながら, そう) are derived in `js/app.js`. An entry stores the
Japanese before the verb (`src`), so if the Notion example changes it is reported
as stale and the app falls back to the original sentence instead of a wrong
translation. New verbs show up under `--todo`: translate them in a new
`translations/es/NNN.txt` following the conventions at the top of `001.txt`.

`build_verbs.py` skips grammar auxiliaries (〜てある, てみる, てもらう…), merges
duplicate senses, and overrides 14 rows whose Notion `Grupo` is wrong
(see `GROUP_FIXES`; remove an entry once it is fixed in Notion).

## Grammar fichas (`gramatica/`)

63 hand-written grammar sheets in Spanish (N5 → N3), served at `gramatica/`.
Each `NN-slug.html` holds its content plus, at most, a `<style>` with its own figure rules;
the shared look comes from `css/tokens.css` (site palette, light and dark) and `css/ficha.css`.
Colours in a ficha's own rules must be tokens (`var(--accent)`, `var(--surface)`…), never hex,
or dark mode breaks. The study order and block texts live in
`gramatica/bloques.json`; everything else is generated from it:

```bash
python3 scripts/build_gramatica.py          # gramatica/index.html + nav inside each ficha
python3 scripts/build_gramatica.py --list   # block, level and title of every ficha
```

The build fails if a ficha is missing from `bloques.json` (or vice versa). It owns the
`<!--gen-head-->`, `<!--gen-top-->` and `<!--gen-bottom-->` regions of each ficha (title,
link back to the index, previous/next); do not edit those or `gramatica/index.html` by hand.
The tutoring workflow that writes the fichas is in `../fichas/AGENTS.md`.

## Deploying

GitHub Pages lets browsers cache assets for 10 minutes, so after changing
anything under `js/`, `css/` or `data/` run `scripts/bump_version.sh` before
committing; it stamps a fresh `?v=` on every asset link.

## Run locally

Open `index.html` directly, or `python3 -m http.server` and visit http://localhost:8000.
